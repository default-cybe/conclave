# Benchmark run 3: the second Claude account, two repeats (2026-10-18)

Three arms on the same 18 tasks, each task run twice, 108 runs in all. Model `<acct2>/claude-sonnet-5-5` (a second Claude subscription account on the proxy) through CLIProxyAPI on `<bench-container>`. Run 2 is in [2026-10-18-run2.md](2026-10-18-run2.md).

- **A:** Conclave's coder agent at b16ee74: harness round 2, the memory round, built-in subscriptions and the desktop daemon merged. 13 tools, effort medium, 5 minute cache.
- **A+skills:** A with ponytail and caveman installed from the catalog.
- **B:** Claude Code 2.1.302 in `-p` mode.

The `<acct2>/` account adds about 335 input tokens to every request in both arms, so totals do not compare with runs 1 and 2. Compare the ratios.

## Short answer

- **Quality:** A passed 35 of 35 counted runs, A+skills 34 of 35, B 35 of 36. The two failures are the same model miss on pg-go-forth (negative numbers), one in B and one in A+skills; the other repeat passed in both. Both still said DONE.
- **Judges:** both prefer Conclave.
  - GPT (gpt-6.1-sol): A 21, A+skills 6, B 3, ties 6.
  - Claude (<acct2>/claude-sonnet-5-5): A 11, A+skills 6, B 4, ties 15.
- **Why the judges pick A:** A adds a regression test almost every time; B often adds none. The GPT notes say "adds no regression test" for B in 9 of its 36 runs, and never for A.
- **Cost:** A costs more than Claude Code this time: A/B list cost 1.18 (90% interval 1.03 to 1.35), up from 1.04. Tokens are even: 0.98 (0.82 to 1.19).
- **Time:** A is slower, 1.37x (1.18 to 1.61). Median run 21 s against 17 s.
- **Why the gap grew:**
  - B got leaner: median 4 turns and 3 tool calls, down from 5 and 4.
  - A's first request grew by about 2,100 tokens since run 2. Its system prompt is 2,067 chars longer (9,340 to 11,407), from the lines the memory round and harness round 2 added.
  - A does more work per run: 6 turns and 9 tool calls. It checks its test fails without the fix in 12 of 36 runs and extends existing test files in 18; B does neither check and extends tests in 9.
- **Noise:** with two repeats the pass result changed between repeats in 0 of 17 tasks for A, 1 of 17 for A+skills and 1 of 18 for B.
- **Kit problems found:** two A runs were dropped as "leak suspects" when they were only failed calls on a wrong path. Fixed in 54e4574; see below.

## Findings from run 3, and what was done

1. **Two runs were dropped for no reason.**
   - rhsma3 (A) sent Edit to `/tmp/conclave-bench/run3/tests/test_api.py`, dropping the run id and `repo/`. revcda (A+skills) sent Read and then Edit to paths with one segment dropped. All three calls failed with "does not exist", so nothing was read or written, but the kit counted any path under the work root outside the run's own folder as a leak.
   - Fixed in 54e4574: a failed file call on a path that does not exist is a "path slip" with its own row. A call that reached another run, or any try at a hidden path, is still a leak. Tests added.
2. **Path slips are a Conclave problem.** A made 3 such calls in 3 runs and A+skills 7 in 6 runs; Claude Code made none, because it uses relative paths through Bash. The "Did you mean" hint helps, but the model can slip again on the next call.
   - In progress: Read, Edit and Write will take a path relative to the session folder (ponytail run on the hub runtime).
3. **The main judge changed between runs.** The report used whichever judge file sorted first by name: Claude in run 2, GPT in run 3.
   - Fixed in 54e4574: a judge of another model family than the arms' model comes first, since it cannot favour its own family's code. For these Claude runs that is GPT.
4. **No cache prefix breaks in any run of any set.** Every request read exactly what the one before read plus wrote. These tasks are short (at most 17 turns) with no subagents and no compaction, so they cannot show round 2's cache work. A long task set would.
5. **ToolSearch and the background task tools were never called.** ToolSearch only appears with MCP servers, and the bench has none.
6. **A's own test files sat at a hidden test path in 6 runs** (forth_test.go, word_search_test.go, tests/xorcism.rs). The kit moved them aside before scoring, as designed. Run 2 had none.
