# Benchmark run 1: Conclave vs Claude Code (2026-10-17)

Arm A is Conclave's coder agent. Arm B is Claude Code 2.1.302 in `-p` mode. Both used `claude-sonnet-5-5` through the same CLIProxyAPI on the bench server (`<bench-container>`). 18 tasks, one run per task per arm, blind judge.

## Short answer

- **Quality:** a tie on correctness. Set 1: both 18 of 18. Set 2: A 17, B 18, and A's one miss was a Conclave bug, not a wrong answer.
- **Judge preference:** A on 10 and 11 tasks, B on 3 and 2, the rest tied. A scores higher on correctness and readability, B much higher on minimal change.
- **Cost:** A costs more. Set 1: 1.64x B's list cost and 1.66x the time. Set 2 (effort matched): 1.30x cost and 1.29x time.
- **Tokens:** not clearly different (1.15x, then 0.95x).
- **Why A costs more:** more turns, more output tokens, 1 hour cache writes, and in set 1 no effort setting.
- **Caveat:** the judge was `claude-sonnet-5-5`, the same model as both agents. A GPT re-judge is planned (see the end).
- **No skills on either side:** neither arm had skills or plugins loaded. A had no ponytail and no caveman; Claude Code had a clean home.

### Where A's extra calls and turns come from

- **Call style.** Claude Code does almost everything in Bash: one `cat a b c d` reads four files, and it edits with heredocs or sed. Over all 18 runs B used Bash 67 times, Read 4, Write 2, Edit 0. Conclave's prompt requires Read, Edit and Write, which gives clean diffs. So "11 vs 4 calls" mostly measures this rule, not extra work. A already batches its calls within a turn.
- **Turns are what cost money,** because each turn re-reads the whole context. A's extra turns come from four places:
  - A first turn of TodoWrite and LS before reading anything.
  - Code, then tests, then test fixes, each in its own turn.
  - Guessing the test command (purge tried 3).
  - Recovering from bad calls.

## Side findings

### Title calls (set 1)

Conclave makes one Haiku 4.5 call per run to name the chat, with max_tokens 30. In 14 of 18 runs it hit the limit, and only 2 of 18 titles were clean.
- **What went wrong:** Haiku starts doing the task instead of naming it ("I'll implement...", "Let me start by exploring...", "# Investigation and Fix...", even "Claude Code: ..."). Four sessions kept "New chat" even though text came back.
- **Cause:** the instruction and the task text go in one user message with no system prompt, so the task text wins.
- **Cost:** negligible (9,182 tokens over 18 calls), but the titles are bad.

### New test files

A added a new test file in 3 of 18 runs in each set: forth_test.go, word_search_test.go, tests/xorcism.rs. B did so once (test/timezone.test.ts in set 1).
- **The judge was wrong** about these. It said forth_test.go and word_search_test.go "may not compile" because they use `testCases`. That variable is defined in the visible cases_test.go in both Go repos. All of these files compile and pass on their own.
- **Side effect in the kit:** each of these files has the same name as a hidden test file. Scoring deletes and replaces them, so the agent's own tests never run there.

## The one real failure (set 2, feat-ts-json, A, run r4e37h)

This was a Conclave bug, not a wrong answer.
1. In one turn the model sent three tool calls:
   - an Edit that worked
   - a MultiEdit with `edits` as a JSON string instead of a list (rejected)
   - a call to an unknown tool named `x` (rejected)
2. Conclave's next request ended with an assistant message instead of the tool results.
3. The API returned 400: "This model does not support assistant message prefill." Conclave exited with code 1, and nothing retried.

The same task passed in set 1. Without this bug, set 2 would also be 18 of 18 for both. Claude Code got an unknown tool call (lowercase `bash`) three times and carried on each time.

The two wrong-path Reads earlier in that run were a model slip: the working directory was stated correctly and the model dropped `repo/`. The error message let it fix itself on the next turn.

## False alarms in the benchmark kit

| flag | what it said | what it was |
|---|---|---|
| hidden test line shown (set 1, rx7de3) | A saw a hidden test line it did not write | A wrote that line itself through MultiEdit. The leak checker misses text nested in `edits[]` with escaped quotes. The line comes from visible test data. |
| reverted edits (A 5 and 2, B 0 and 4) | edits undone and redone | Every one was `git stash`, run the test, `git stash pop`: the agent checking that its new test fails without the fix. That is good practice. |
| tamper flags (about 9 per arm per set) | changed existing tests | Agents only added tests to existing test files. No test was removed or weakened (the judge agrees: 0 tampering). |

## Why A costs more, in order

1. **Effort.** In set 1, A sent no effort setting; Claude Code sent medium. Matching it cut A's total cost from $2.41 to $1.83 and its time from 617 s to 465 s. B barely moved.
2. **More turns and output.** Median 6 turns against 5, and 1.5x to 2.2x more output tokens. A writes regression tests and comments more often. The judge likes that for correctness and readability, but marks it down on minimal change.
3. **1 hour cache writes.** All of A's cache writes are at the 1 hour price (2x input), while B's are at 5 minutes (1.25x). For a run that finishes in under a minute, the 1 hour cache buys nothing.
4. **The system prompt.** A's rules ask for things B does not do: a regression test, comments, a separate check step. That is where most of the minimal change gap comes from.

- **Skills arm:** a third arm, Conclave with ponytail ("write less code") and caveman installed from the catalog, to test whether they close the minimal change and output gaps.
- **Rerun:** both sets again with arms A (new prompt), A+skills and B, judged by GPT and Claude.
