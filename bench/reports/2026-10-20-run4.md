# Benchmark run 4: the Anthropic API and a shorter prompt (2026-10-20)

Three arms on the same 18 tasks, each task run twice, 108 runs in all. Model `claude-sonnet-5-5` straight on the Anthropic API with the owner's key, so neither arm pays the proxy's extra tokens of run 3. The GPT judge stayed on CLIProxyAPI. Run 3 is in [2026-10-18-run3.md](2026-10-18-run3.md).

- **A:** Conclave's coder agent at ff62ecc: every ponytail fix merged, and the base prompt leaves out its memory and skill rules when those tools are off (44be4f0).
- **A+skills:** A with `plugin:ponytail` only. Run 3 also had caveman.
- **B:** Claude Code 2.1.302 in `-p` mode.

## Short answer

- **Quality:** A 36 of 36, B 36 of 36, A+skills 34 of 36. Both A+skills failures said DONE: pg-go-forth r2 (negative numbers, the same miss as run 3) and pg-go-word-search r2 (6 of 24 hidden tests failed).
- **Cost:** A is cheaper than Claude Code for the first time.
  - List cost A/B 0.89 (90% interval 0.81 to 0.98).
  - Tokens A/B 0.74 (0.65 to 0.84).
  - Wall time even: 0.99 (0.88 to 1.11).
- **Judges:** both prefer A.
  - GPT (gpt-6.1-sol): A 14, B 9, A+skills 2, ties 11.
  - Claude (claude-sonnet-5-5): A 12, A+skills 4, B 3, ties 17.
- **Why A got cheaper:**
  - System prompt 11,407 to 9,466 chars; first request 13,105 to 11,844 tokens.
  - Output per run 3,062 to 2,372 tokens (23% less). Output is the priciest token.
  - Median turns and tool calls 6 and 9 to 5 and 7.
- **What A did less of:** the check that a new test fails without the fix fell from 12 of 36 runs to 1. The model skipped it; the prompt trim is not the cause (see [Test check](#test-check)). It still extended existing test files in 14 runs against B's 10, and GPT's notes say A left out a regression test in 2 runs against 9 for B.
- **Wasted turns:** 11 of 36 A runs read files with `cat`, then had every Edit refused for lack of a Read and spent a turn on Reads. Fixed after the run (see [Test check](#test-check)).
- **Ponytail as a skill does not pay:** lowest correctness and readability from both judges, both failures, 1,694 more tokens per request, and no regression test in 9 of 36 runs. It stays out of the defaults.
- **Spend:** about $11.70 on the API: $6.96 for the 108 agent runs and $4.76 for the Claude judge.

## Test check

**The model skipped the check; no tool broke it.** From the run 3 and run 4 transcripts:

| runs with a real `git stash` check | A | A+skills | B |
|---|---|---|---|
| run 3 | 12 of 36 (all 12 bug runs) | 9 of 36 | 1 of 36 |
| run 4 | 1 of 36 (bug-py-utf8 r1) | 0 of 36 | 5 of 36 |

- The coder prompt line is the same at b16ee74 and ff62ecc. Bench runs use bypass mode, so the Bash rules do not block it. The one check A ran worked, with its `timeout 30` guard.
- A's final text mentions a "fails without the fix" step in 12 of 12 bug runs in run 3 and 2 of 12 in run 4.
- What changed between the runs for A: the API route (run 3's second account added about 335 tokens of its own system text to every request) and the prompt trim.
- **The trim is not the cause.** Set run4-notrim-bugs ran the same 12 bug runs for A on the API at ff62ecc with only 44be4f0 undone:

| A, 6 bug tasks x 2 | route | prompt | system chars | stash check | final text mentions it | Edit before Read | list cost |
|---|---|---|---|---|---|---|---|
| run 3 (b16ee74) | second account | untrimmed | 11,407 | 12 of 12 | 12 of 12 | | |
| run 4 (ff62ecc) | API key | trimmed | 9,480 | 1 of 12 | 2 of 12 | 6 calls in 5 runs | $0.77 |
| run4-notrim-bugs | API key | untrimmed | 11,429 | 3 of 12 | 3 of 12 | 10 calls in 7 runs | $0.87 |

- The untrimmed prompt brings back 2 of the 11 missing checks and costs 13% more. Most of the drop came with the move from the second account to the API: likely the account's own system text, which run 3's A had on every request. The proxy's Claude logins failed during the follow up, so a run of ff62ecc on the second account to confirm it is still to do.
- B moved the other way on the same switch (1 check in run 3, 5 in run 4).

**Why A's failed tool rate rose (5% to 11%):** Edit before Read.

| A's failed calls | run 3 | run 4 |
|---|---|---|
| Edit before Read ("File has not been read yet") | 18 in 8 runs | 32 in 11 runs |
| `python: command not found` (the server has only python3) | 1 | 4 |
| wrong path | 4 | 2 |
| old_string not found | 4 | 0 |
| other Bash non-zero (probing for tsc with `ls ... \| grep tsc`, a missing tests/) | 2 | 4 |

- The pattern: A reads the files with `cat` in Bash, sends all its Edits in one turn, every Edit fails because the read tracker counts only the Read tool, then it spends a turn on Reads and sends the Edits again. In feat-py-attempts and feat-ts-json that was 7 or 8 failed Edits in one run.
- Fixed after the run: Edit and MultiEdit now accept a file the agent never read when every old_string matches exactly (no whitespace or quote fallback) and a Read of that file would be allowed. A Read deny rule still blocks it, and Write still needs a Read. The error now says that `cat` output does not count.

**What the GPT notes say, by theme:**
- **Regression tests:** the notes say a run added no regression test for A in 2 runs (pg-rs-luhn-from r1, pg-rs-xorcism r1), for B in 9 and for A+skills in 9. A+skills left them out in both repeats of bug-py-retry, bug-py-utf8 and bug-ts-cents.
- **Test placement:** B put its new test class after `unittest.main()` in bug-py-utf8 r2 and in both feat-py-purge runs, so a direct run of the file skips the new tests. Run 3 had the same in feat-py-purge.
- **Type errors:** B's feat-ts-money r2 imports `currencyInfo` three times, which fails a TypeScript check although the tests pass.
- **Empty values:** in bug-ts-config, B r1 and A+skills r2 skipped falsy values, so an explicit empty setting falls back to a lower layer instead of reaching validation. A skipped only undefined values in both runs.
- **Ponytail's short code:** A+skills got notes on dense one-line expressions in pg-py-bowling (both repeats), feat-ts-json and bug-py-cursor r2, and repeated graph traversal with exponential work in pg-js-react (both repeats).
- **Shared misses:** every arm missed definition-time binding in pg-go-forth, and every arm let negative timestamps encode but fail to decode in bug-py-cursor.
