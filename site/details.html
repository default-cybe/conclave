Conclave in detail

Every feature, why it is built this way, how it compares, and its limits today.

01 Features

What it does

One hub holds every chat, session, memory, routine and key. The apps on each device talk to it, and the computers you pair do the work.

01

Chat with any model

Home opens on a chat, like ChatGPT or claude.ai. Pick Claude, GPT, Gemini, GLM, a model on OpenRouter or one on your own machine. Turn thinking, web search and memory on or off for each chat.

  • Second opinion. Send any reply to another model and read its answer in line.
  • Jury and debate. Several models answer, then a judge sums up or votes. Juror names can be hidden from the judge.
  • Handoff. Switch the model in the middle of a chat and keep going.
  • Edit, retry, branch, and preview an HTML or SVG answer in a sandbox.
  • When a chat needs files or a shell, Continue as session moves it over.

02

Code on your own computers

A session is an agent at work in a folder, on the hub or on any PC or Mac you pair. The agent loop runs on the hub and the tools run on the computer you pick. The desktop app carries the small program that lets the hub use that computer, and it connects out, so no port opens.

  • Conclave's own agent loop gives any model file, shell, search, web, browser and subagent tools.
  • Claude Code, Codex, Gemini CLI and OpenCode run inside Conclave too. Their permission prompts become Conclave approvals.
  • A checkpoint before each turn, so any change is one click to undo, even outside a git repository.
  • After a turn that edited files, the project's check runs on that computer before the turn may end.
  • The slash menu of Claude Code, with your commands and skills.

03

Projects that follow you

Sessions group by project or by device. Start on the PC and go on from the Mac, even when the project sits at another path there. Conclave finds the folder by its git history, Syncthing or a path it learned, and says how sure it is.

  • Repo sessions. Pick a GitHub repository, and the session gets its own git worktree on a new branch, on the hub or a paired computer.
  • Open pull request drafts the title and body from the session. The pull request's state and checks show in the session, and Clean up removes the worktree after the merge.
  • The GitHub token stays with the hub. Sessions never see it. Never a force push, never the default branch.

04

Approve from anywhere

Risky commands wait for you. Allow or Deny from the Inbox, from the conversation, or right on the notification on your phone.

  • Allow, ask and deny rules in Claude Code's syntax, permission modes, and a full audit log.
  • A guard asks before rm -rf /, mkfs, force pushes to main and the like, in every mode.
  • Agents that read mail or web pages get only the tools their rules name, and every other call asks.
  • Alerts when a session makes no progress for 5 minutes, or when two chats edit the same file.
  • Notifications come from the hub itself: Web Push, the desktop tray and the Android app's own connection. No outside service. They stay quiet while you are at the desk.

05

The Map

One page shows everything the hub is doing. The hub's knot sits in the middle, devices and projects branch off it, and every chat, session, subagent and workflow agent of the last 24 hours is a dot: violet while it runs, amber while it waits on you.

  • Streams follow each agent's token rate to its project and on to the hub.
  • Open a node for its model, device, last tools, usage, and Stop.
  • Stuck agents and file conflicts are drawn on the map.
  • Replay scrubs back through the day.

06

Workflows: many agents, checked in code

A workflow is a script that sends work out to many subagents and checks what they claim. Scripts in Claude Code's workflow format run as they are.

  • Twelve ship, among them review changes, deep research, fix until green, fix an issue, bug hunt and security audit.
  • A refuter panel tries to disprove each finding, and a quote must sit within 3 lines of the line it cites.
  • Runs resume after a crash, keep to a budget, and give risky agents their own git worktree.
  • Specialist agents (builder, tester, debugger, verifier, fact-checker and more) ask for a fast, smart or deep model.

07

Friends, hub to hub

Send a chat, a session or code from your hub to a friend's hub. There is no service in the middle, and nothing is reachable without a friend's key.

  • Invite with a link or a QR code, then compare a safety code.
  • Before you send, a review shows what it took out: secrets, emails, private addresses, device names and home paths.
  • Your friend can fork it, hand it off, keep it as a reference, or apply the code to a new branch.
  • Unsend asks their hub to delete its copy.
  • Shared projects: one repo with a friend, with shared notes and chats, and code through GitHub.
  • A friend's message is data. It cannot approve or run anything.

Also in the box

Memory

One memory for every model and device: a profile, facts recalled when they matter, and summaries of past sessions. It mirrors to Basic Memory notes, and claude.ai and ChatGPT can read it as a connector.

Past chats

Import Claude Code, Codex and Gemini CLI chats from any paired computer, and claude.ai or ChatGPT exports. Learn from them or not. A cost estimate comes first, and Undo works for 30 days.

Routines

Agents on a schedule or a webhook. 21 suggestions, from a server watchdog to a CVE watch. Each has its own allow list, and missed runs catch up after downtime.

The assistant

Goals with a progress history, a morning brief, an evening wrap-up and a weekly review. It reads your calendars (Nextcloud, iCloud, Google, Outlook) and mail, finds free time, and proposes events and drafts that wait for your OK. Places, directions and when to leave, through OpenStreetMap or Google Maps. Routine messages wait for the hours you set.

Watches

Ask the assistant to keep an eye on a site, such as used cars under a price. It checks on a schedule in its own browser and tells you what is new, what is gone and what got cheaper. Watches show on the Routines page.

People on your hub

Invite a few people to your hub. Each gets their own chats, memory, keys and devices, and sees nothing of yours. They bring their own keys, or you share yours with a monthly limit.

Usage and limits

5 hour and weekly windows, spend per model, account and key, cache savings, and a budget per API key. A session that hits a limit waits and goes on when it resets.

Models and plans

Anthropic, OpenAI, Gemini, Z.ai GLM, OpenRouter, DeepSeek, Kimi, Qwen, Ollama, LM Studio and any OpenAI-compatible endpoint. Sign in with your Claude, ChatGPT and Google plans, set their order, and fall back to an API key.

Agents

Agents are Markdown profiles in Claude Code's format: model, tools, skills, MCP servers, permissions and device. 24 ship, each tried against a real model.

Extensions

Skills, slash commands, hooks, plugins and MCP servers in Claude Code's formats, so an existing ~/.claude setup works. Discover finds more on GitHub and shows every file before you add it.

Remote access

Phones on your Wi-Fi pair at once. One switch gives the hub an https address through a Cloudflare tunnel it runs itself, with no account. Or use your own domain, Tailscale or a reverse proxy.

First run

A ten step setup covers remote access, keys (each tested when you paste it), coding tools on each computer, models, memory, import and pairing. Every step can be skipped.

Terminal

conclave opens a chat in your terminal, and conclave run does one task headless, for scripts. The desktop app puts it on your PATH, signed in to your hub.

Install

The hub runs in Docker Compose, a Proxmox container made by one script, or any LXC container or VM. Desktop apps for Linux, macOS and Windows carry the device program, and can run the hub themselves on a computer with no server.

03 Why

Why it is built this way

Yours to run

A hub you own

One database, one memory and one scheduler, and every app talks to one place. Your chats, code and keys stay on hardware you control. The makers of Conclave never receive them.

Docker or LXC

Docker Compose runs anywhere Docker does. A Proxmox or other LXC container is how many homelabs already run services, and it gets its own address on your network, so phones connect at once. In an LXC container or VM the code belongs to root, so the hub's own agents cannot change it.

SQLite, not Postgres

This is personal scale. One file is easy to back up, and SQLite's built-in full text search covers chats and memory.

Remote access with no account

Claude Code works anywhere because Anthropic runs the relay. Conclave runs its own Cloudflare quick tunnel instead, needs no account, and keeps it off until you turn it on. Apps check the hub's key before they send a token, so a stranger at an old address gets nothing.

Notifications with no outside service

Notices stay inside Conclave, with nothing else to set up. The hub makes its own Web Push keys, and the Android app keeps its own connection to the hub instead of using Firebase.

Friends with no server

Shared links leak, and a friend's text can steer a model. So a hub's key is its identity, messages are sealed end to end, and what a friend sends stays quoted data until you adopt it.

Careful by default

Approvals by default

An agent that runs commands on your computers should ask before anything risky, and you should be able to answer from wherever you are. Text from mail or a web page can try to steer a model, so those sessions get only the tools their rules name.

Computers connect out

Each computer connects out to the hub, so none opens a port. The program that does this in the desktop app is written in Rust because it runs all the time on every machine: 4.9 MB, about 7 MB of memory.

Memory holds facts, not orders

A note saved as "Always answer short" is read back later as an instruction and can beat what you ask for then. So memory keeps facts, and an item learned from a chat stays only when its quote is really in that chat.

Checks in code, not in the prompt

Persona openers showed no accuracy gain across 162 personas (Zheng et al.). What cuts false positives is structure: finders report everything, then a verifier in a fresh context tries to refute each finding.

Built from what works

Its own agent loop, and the vendors' too

Conclave's loop, rebuilt from Claude Code's public design, gives GLM, GPT, Gemini or a local model the same good tools, and lets models join each other's chats. When you want a vendor's tuned loop, Conclave runs Claude Code, Codex, Gemini CLI or OpenCode instead.

Plans, keys and local models

You may already pay for Claude, ChatGPT or Google plans. Their sign-in and request shapes change every few weeks, and CLIProxyAPI already keeps up, so the hub runs a pinned, checksum-checked copy instead of rebuilding it. API keys cover unattended work, and local models cover the rest.

The Map

Conclave runs many chats, subagents and workflow agents at once. One live page shows what runs, what waits on you and what is stuck, with work visibly flowing toward the hub.

Compaction and the prompt cache

At 80% of the context window a session is summarized into a fixed template (objective, constraints, decisions, work state, files, next step and more), merged into the last summary and checked before use. The system prompt stays byte for byte the same, and old tool output is cleared in batches, so the cache misses once per batch instead of every turn.

The phone design

On a phone the conversation fills the screen and the rest lives in a side panel, the shape people know from the claude.ai app. Token and cost lines move to a sheet, and an approval sits at the end of the chat as three full width buttons.

Where they are better

  • Claude and ChatGPT need no setup, have polished native apps everywhere, and get their makers' new features first.
  • Claude Code and Codex are each vendor's own loop, tuned for its models. Conclave can run them, but it does not change them.
  • Cursor is a full editor with completions, and its cloud agents start in ready machines.
  • GitHub Copilot lives in GitHub, from issue to pull request, with controls for organizations.
  • Open WebUI and LibreChat are built for many users, with roles and permissions. Conclave is built for one owner and a few people they invite, without roles for a whole organization.
  • All of them have far more users behind them. Conclave is new, at its first releases.

05 Limits

Limits today

Every feature in the design log ends with where it can fail. These are the ones you would notice first.

  • Accounts are for a few people you trust. Web search, embeddings and maps run on the owner's keys, and friends between hubs belong to the owner.
  • A quick tunnel's address changes when the hub restarts. The iPhone home screen app and the claude.ai and ChatGPT connectors need a stable address, such as your own Cloudflare domain.
  • A provider may treat plan sign-in through CLIProxyAPI as against its terms. That call is yours. Unattended work belongs on API keys.
  • Tools run as the hub's user. The guard on the hub's secrets stops mistakes and instructions from web pages, not a script that tries hard.
  • Alerts live in memory, so a hub restart drops them. A file changed by a shell command does not count as a conflict.
  • The share review finds what looks like a secret. A password written out in plain words still goes unless you spot it.
  • Android cannot start a repo session or a workflow from the library yet.
  • Repo sessions and applying a friend's code need a POSIX shell and git on the device. Windows devices are not supported there.
  • The desktop apps are not signed yet, so macOS and Windows warn the first time you open them.
  • The check that keeps memory to facts works in English only.
